# 热压排程（hot-press-scheduling）

> 面向多品种、小尺寸成型产品的热压工序排程（APS）：把客户订单拆成热压工单，按机台、模具、人工与前置期约束排出可执行的班次计划，并解释每一个排程决定。

这是一个真实工厂排程需求的算法设计与 Python 参考实现。核心引擎零第三方依赖，配一个**独立于引擎**的约束校验器——排完不靠引擎自证合规，而是由 739 行的校验器按 C01–C16 逐条判定。

本项目只排**第一道热压**工序。进桶/滚筒、摆牌、点漆不在范围内，但输出会带**可释放数量与预计释放时间**，作为工序间接口。

## 它能做什么

### 订单 → 可执行班次计划

输入客户订单、机台与模具资源、人员班次，输出每个热压工单落在哪台机、哪个班次、什么时候能交付。现场口径（2026-10-22 确认）：

| 项 | 值 |
|---|---|
| 热压机 | 38 台 |
| 操作工 | 19 人，一人两台，同时开 19 台 |
| 前置期 | 15 天 |
| 排程范围 | 仅热压，下游工序不排 |
| 工单来源 | 金蝶 K3《生产任务单序时簿》，全厂 43,967 行 |

口径优先级：**客户书面需求 > 现场确认 > 真实数据 > 设计稿/参考实现**，冲突按此顺序裁决并在背景文档留痕。

### 每个决定都带解释

排程结果不只是「排在哪」，还给出**为什么这样排**：为什么选这台机（模具匹配 / 空闲窗口 / 换模代价）、为什么排这个班次、为什么这个单被延期。解释由 `engine/explain.py` 生成，是给车间看的，不是调试日志。

### 约束校验与引擎分离

`verify/constraint_checker.py`（739 行）独立实现 C01–C16 共 16 条约束判定，跑完排程即可判定是否违规。它不调用引擎内部状态，只吃「输入 + 排程结果」，所以引擎改算法不会让校验跟着一起错。

### 产能、换模、日历与延期分开算

排程主流程之外，每个关注点都是独立模块，可单独测：

- `engine/capacity.py` 产能核算（机台工时 × 人力）
- `engine/molding.py` 模具匹配与换模代价（含真实换模的 C08 校验）
- `engine/calendar.py` 班次日历（哪些时段可排）
- `engine/delay.py` 延期与前置期判定
- `engine/scheduling.py` 择优与贪心填充

### 真实 ERP 数据可接入

`ingest/erp.py` 解析金蝶 K3 导出的 `.xls`（BIFF 二进制，标准库无法解析，因此作为**可选依赖** `xlrd`）。不装可选依赖也能跑全部测试——核心引擎不碰 ERP 格式。

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Python ≥ 3.14 | `pyproject.toml` 的 `requires-python` |
| 核心引擎 | 纯标准库 | 零第三方依赖：贪心填充 + 择优、产能核算、换模、班次日历、延期判定、解释生成 |
| 校验 | 独立约束校验器 | C01–C16，与引擎解耦，只依赖输入与输出 |
| 数据接入 | `xlrd`（可选） | 仅用于读金蝶 K3 的 `.xls` 导出 |
| 测试 | 六个独立脚本 | 场景 / 负例 / 稳定性 / 金样回归 / 单元 / 自检，全部以退出码 0 为通过 |

## 快速开始

```bash
pip install -e ".[erp]"     # 只有需要读 .xls 工单时才装可选依赖
```

全部测试入口在 `prototype/` 下逐个执行，退出码 0 即通过：

```bash
cd prototype
python tests/selftest.py        # 约束 C01-C16 校验（含真实换模的 C08），由 verify/constraint_checker.py 判定
python tests/scenarios.py       # 场景用例，输出「通过 64/64」
python tests/negative_check.py  # 负例，输出「通过 27/27」
python tests/stability.py       # 输入扰动稳定性，输出「通过 17/17」
python tests/golden.py          # 金样回归，输出「通过 22/22」
python tests/units.py           # 单元测试，输出「通过 5/5」
```

另有几个探针脚本（产出数据而非断言）：`benchmark.py`（性能）、`sensitivity.py`（参数敏感性）、`hash_probe.py`（哈希稳定性）、`demo_cases.py`、`real_data.py`、`ingest_erp.py`（真实工单导入演练）。

## 目录结构

```
prototype/
  domain/models.py             # 领域模型：工单、机台、模具、班次
  engine/scheduler.py          # 排程主流程（1045 行）
  engine/scheduling.py         # 择优与贪心填充
  engine/capacity.py           # 产能核算
  engine/molding.py            # 模具与换模
  engine/calendar.py           # 班次日历
  engine/delay.py              # 延期与前置期
  engine/explain.py            # 排程解释（每个决定给出依据）
  ingest/erp.py                # 金蝶 K3 .xls 导出解析（可选依赖 xlrd）
  verify/constraint_checker.py # 约束校验器 C01-C16（739 行，独立于引擎）
  tests/                       # 场景/负例/稳定性/金样/单测 + 探针脚本
```

## 已知限制

- 下游工序不排，只给「可释放数量 / 预计释放时间」，下游是否吃得下需另行评估。
- 资源数据存在口径缺口，见 `热压排程资源数据口径缺口清单.md`；排程结论建立在文中列明的假设之上。
- 结构性假设的影响范围见 `热压排程结构性假设影响评估.md`，改动假设后必须重跑 `tests/golden.py`。
- 排程目标是可行与可解释，不是全局最优——没有引入 MILP/CP 求解器，规模上去后需要重新评估。
